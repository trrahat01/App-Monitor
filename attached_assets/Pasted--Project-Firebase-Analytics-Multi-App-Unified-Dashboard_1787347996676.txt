## Project: Firebase Analytics Multi-App Unified Dashboard

Develop a production-ready web dashboard that aggregates Firebase/Google Analytics data from multiple Android applications into one unified analytics platform.

### 1. Core Goal

Create a modern, responsive dashboard where an administrator can connect multiple Firebase projects/apps and view their analytics individually or combined in a single interface.

The dashboard must make it easy to answer:

* How many users are active across all apps?
* Which app has the most users?
* How much engagement are the apps receiving?
* Which apps are growing or declining?
* What is the retention rate?
* Which app/version/country/platform is performing best?

### 2. Dashboard Overview

Create a professional analytics dashboard with:

* Total DAU
* Total WAU
* Total MAU
* Total sessions
* Total engagement time
* Average engagement time per user
* New users
* Returning users
* Retention rate
* User growth percentage
* Total events
* Crash-free users, when available
* Number of connected apps

Show comparison with the previous equivalent period.

Example:

`DAU: 12,450  ↑ 8.4%`

Allow the administrator to select:

* Today
* Yesterday
* Last 7 days
* Last 30 days
* Last 90 days
* Custom date range

### 3. Multi-App Support

Create an application/project management system.

Admin can:

* Add Firebase project
* Remove Firebase project
* Edit project
* Enable/disable project
* Add multiple Android apps
* Assign app names and icons
* Assign categories
* View project status
* Test connection
* Manually refresh analytics

Example:

App 1 — Daily Spark
App 2 — Nursing MCQ
App 3 — Quotes App
App 4 — Travel App

The dashboard should support an unlimited number of connected applications where technically possible.

### 4. Unified Analytics

Provide two viewing modes:

#### All Apps

Aggregate analytics from every connected app.

#### Individual App

Display analytics for only the selected application.

Include a dropdown:

`All Apps ▼`

Changing the selection must update all dashboard metrics and charts.

### 11. Real Firebase Integration

Do NOT create fake analytics data for the production implementation.

Use official Firebase/Google Analytics APIs and authentication mechanisms.

The architecture should support:

* Google OAuth authentication
* Firebase project selection
* Secure project credentials
* Google Analytics/Firebase Analytics data retrieval
* Multiple Firebase projects
* API error handling
* Token expiration handling
* Rate-limit handling

Never expose Firebase service-account private keys or sensitive credentials in frontend code.

All sensitive operations must occur server-side.

Show clear connection states:

* TypeScript

* Responsive design

* TypeScript
* REST API or equivalent

Authentication:

### 14. Data Layer

Create a normalized analytics data model.

Store metadata such as:

* Project ID
* App ID
* App name
* Package name

* Connection status

For analytics, use caching where appropriate to reduce unnecessary API requests.

Do not permanently duplicate large amounts of raw analytics data unless necessary.

### 15. Performance Optimization

The dashboard must be optimized for multiple applications.

Implement:

* Server-side aggregation
* API response caching
* Lazy loading
* Pagination
* Debounced filters
* Efficient database queries
* Parallel API requests where safe
* Background synchronization
* Incremental data refresh
* Error isolation between projects

One failed Firebase project must not cause the entire dashboard to fail.

Example:

`4/5 apps synchronized successfully`

### 16. Synchronization

Add a synchronization system.

Display:

`Last updated: 2 minutes ago`

Provide:

`Refresh Analytics`

Also support automatic synchronization at configurable intervals.

If automatic synchronization is implemented, prevent duplicate API requests and respect API quotas.

### 22. Security

Implement strong security practices.

Requirements:

* Secure authentication

`Firebase permission denied`

`Google Analytics API unavailable`

`Project not found`

`Authentication expired`

`Analytics data unavailable`

`API rate limit reached`

Do not crash the dashboard.

Show a useful error message and allow retry.

### 25. Important Analytics Accuracy Rule

Do not invent Firebase metrics.

If Firebase/Google Analytics does not directly provide a requested metric, clearly identify whether the dashboard is calculating it from available underlying data.

All aggregated metrics must avoid double-counting users where technically possible.

Document exactly how cross-app totals are calculated.

### Final Requirement

Prioritize **real Firebase/Google Analytics integration, security, scalability, accuracy, and performance** over visual mock data.

If an API capability differs between Firebase Analytics and Google Analytics 4, use the appropriate official API and clearly document the limitation rather than pretending the metric exists.

The final result should feel like a professional **Firebase Analytics command center for managing analytics from multiple Android applications in one place**.
